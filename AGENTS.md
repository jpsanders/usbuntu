# AGENTS.md

Instructions for AI coding agents working on usbuntu itself. To use the tool, read `skills/usbuntu/SKILL.md` or run
`usbuntu guide`.

## Commands

```sh
make init-dev     # install the package and the development tools into the active environment
make format       # apply black and isort
make checks       # every check CI runs, in CI's order; run it before you say a change is done
make man          # rebuild the man page and the packaged manual after editing docs/MANUAL.md
```

Use Python 3.15 for development; the package supports 3.14 and later.

## Layout

```text
src/usbuntu/cli.py        the command line
src/usbuntu/devices.py    which disks may be wiped; every refusal rule lives here
src/usbuntu/installer.py  partition, copy, chroot, boot chain, verify
src/usbuntu/layers.py     the ISO's squashfs layer chain
src/usbuntu/runner.py     every external command, echoed to stderr and logged
src/usbuntu/data/         MANUAL.md and usbuntu.1, generated by make man
docs/MANUAL.md            the one source for the guide and the man page
```

## Rules

- Tests never touch a real disk, never mount and never need root. Mock `list_devices` and the runner.
- A new refusal rule belongs in `devices.refusal_reasons`, so `install`, `--device` and `devices` agree.
- Never log or print a password. It reaches the chroot through a pipe.
- mypy runs in strict mode, docstrings use the Sphinx style, lines stop at 120 characters.
- Tags carry the bare version, `1.2.0`, never `v1.2.0`. Add a `CHANGELOG.md` entry for anything a user would notice.
